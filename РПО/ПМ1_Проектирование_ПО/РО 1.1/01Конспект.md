# Программное обеспечение: от идеи до реального мира

## 1. Программное обеспечение в составе компьютерной системы

Компьютерная система состоит из трёх взаимосвязанных частей:

- **Hardware** — аппаратное обеспечение;
- **Software** — программное обеспечение;
- **Data** — данные.

Аппаратное обеспечение — это физические компоненты: процессор, оперативная память, накопители, видеокарта, сетевые устройства и периферия. Оно выполняет вычисления, хранит и передаёт данные.

Программное обеспечение определяет, **что именно должна делать система**, как обрабатывать данные, как взаимодействовать с пользователем и устройствами.

Данные — это информация, с которой работает система: текст, изображения, записи базы данных, файлы, координаты, результаты вычислений и т. д.

Кратко:

> **Hardware выполняет, Software управляет логикой работы, Data — объект обработки.**

---

## 2. Что такое программное обеспечение

Программное обеспечение — это не только приложения, которые пользователь запускает вручную. В современную программную систему могут входить:

- пользовательские приложения;
- серверные программы;
- фоновые службы;
- драйверы;
- библиотеки;
- API;
- базы данных и СУБД;
- встроенное программное обеспечение;
- вспомогательные программные компоненты.

Поэтому ПО лучше рассматривать как **совокупность программ и компонентов**, которые совместно обеспечивают работу вычислительной системы или решают определённую задачу.

---

## 3. Программа, программный компонент и программный продукт

### Программа

Программа — это набор инструкций, которые выполняет вычислительная система. Она может быть очень небольшой и решать одну конкретную задачу.

### Программный компонент

Программный компонент — часть более крупной системы. Он отвечает за отдельную функцию и взаимодействует с другими компонентами через данные, интерфейсы, API, файлы или сетевые протоколы.

Примеры:

- модуль авторизации;
- модуль оплаты;
- служба уведомлений;
- backend-сервис;
- библиотека.

### Программный продукт

Программный продукт — законченное решение, предназначенное для пользователя или организации. Он может включать:

- программный код;
- данные;
- настройки;
- документацию;
- базы данных;
- процессы установки и обновления;
- средства мониторинга;
- правила эксплуатации.

Таким образом, **программа** — это исполняемая логика, **компонент** — часть системы, а **продукт** — готовое решение целиком.

---

## 4. Классификация программного обеспечения по назначению

Основные категории ПО:

1. **системное**;
2. **прикладное**;
3. **инструментальное**.

Главный критерий классификации — **основное назначение программного продукта в конкретной системе**.

---

## 5. Системное программное обеспечение

Системное ПО обеспечивает работу компьютера и взаимодействие программ с аппаратными ресурсами.

К нему относятся:

- операционные системы;
- драйверы;
- системные службы;
- системные утилиты.

### Операционная система

Операционная система управляет:

- процессами;
- памятью;
- файлами;
- устройствами;
- пользователями;
- сетевыми ресурсами.

Примеры: Windows, Linux, Android.

### Драйверы

Драйвер — специализированная программа, которая позволяет операционной системе взаимодействовать с конкретным устройством.

Например, приложение не работает напрямую с видеокартой. Обычно взаимодействие проходит через операционную систему и драйвер.

### Системные службы

Системные службы работают в фоновом режиме и выполняют служебные задачи:

- обновление;
- печать;
- синхронизацию;
- сетевое взаимодействие;
- журналирование;
- мониторинг;
- функции безопасности.

Системное ПО является основой, на которой работают остальные программы.

---

## 6. Прикладное программное обеспечение

Прикладное ПО решает конкретные задачи пользователя или организации.

Примеры:

- мессенджеры;
- браузеры;
- графические редакторы;
- карты и навигация;
- банковские приложения;
- CRM и ERP;
- игры;
- офисные программы.

Форма программы не определяет её класс. Прикладное ПО может быть:

- настольным;
- мобильным;
- веб-приложением;
- частью корпоративной системы.

Главное — оно решает **прикладную задачу конечного пользователя**.

---

## 7. Инструментальное программное обеспечение

Инструментальное ПО используется разработчиками для создания, проверки и сопровождения других программ.

Основные группы инструментов:

- редакторы кода и IDE;
- компиляторы и интерпретаторы;
- отладчики;
- системы контроля версий;
- средства тестирования;
- инструменты сборки;
- средства развёртывания.

### Примеры

- Visual Studio Code;
- PyCharm;
- Visual Studio;
- Git;
- компиляторы;
- отладчики;
- тестовые фреймворки.

Инструментальное ПО поддерживает весь цикл работы разработчика:

> **написать → проверить → протестировать → собрать → развернуть**

---

## 8. Почему классификация ПО не всегда однозначна

Один и тот же продукт может выполнять разные роли в зависимости от контекста.

### Google Chrome

Для обычного пользователя Chrome — прикладное ПО, потому что используется для просмотра сайтов и работы с веб-приложениями.

Для веб-разработчика браузер дополнительно становится инструментом разработки благодаря DevTools.

### Git

Для обычного пользователя Git может быть вообще не нужен. Для разработчика это важный инструмент управления версиями исходного кода.

### PostgreSQL

PostgreSQL — это **СУБД**, то есть программное обеспечение.

При этом база данных — не программа, а организованная совокупность данных.

Важно различать:

- **СУБД** — программа для управления данными;
- **база данных** — сами структурированные данные.

---

## 9. Программа не обязана иметь графический интерфейс

Наличие окна не является обязательным признаком программы.

Без графического интерфейса могут работать:

- фоновые службы;
- серверные приложения;
- планировщики задач;
- службы синхронизации;
- системы мониторинга;
- программы микроконтроллеров;
- ПО маршрутизаторов;
- встроенные системы автомобиля;
- контроллеры бытовой техники.

Программа может выполнять свою задачу полностью автоматически и вообще не взаимодействовать с пользователем напрямую.

---

## 10. Современная программная система состоит из уровней

Большинство реальных программных продуктов состоит не из одного файла, а из нескольких взаимосвязанных уровней.

### Пользовательский уровень

Интерфейс, с которым работает пользователь:

- сайт;
- мобильное приложение;
- desktop-программа.

### Логика приложения

Здесь находятся:

- правила обработки действий;
- бизнес-логика;
- проверки;
- алгоритмы;
- серверная логика.

### Данные и сервисы

К этому уровню относятся:

- базы данных;
- API;
- файловые хранилища;
- внешние сервисы;
- очереди сообщений.

### Системный уровень

Он включает:

- операционную систему;
- сетевой стек;
- драйверы;
- аппаратные ресурсы.

Чем сложнее система, тем важнее согласовать взаимодействие между уровнями.

Особое значение имеют:

- формат данных;
- единицы измерения;
- структура запросов;
- права доступа;
- обработка ошибок;
- ожидаемое поведение компонентов.

---

## 11. Пример системы доставки еды

Типичная схема:

> **Пользователь → мобильное приложение → backend → PostgreSQL**

Роли элементов:

- мобильное приложение — прикладное ПО;
- backend — серверная логика;
- Linux на сервере — системное ПО;
- VS Code и Git — инструментальное ПО;
- PostgreSQL — СУБД;
- заказы, пользователи и другие записи — данные.

Даже если каждый компонент работает отдельно правильно, система может работать некорректно, если компоненты используют разные форматы данных или несовместимые интерфейсы.

Поэтому корректность всей системы зависит не только от отдельных программ, но и от качества их взаимодействия.

---

## 12. Разработчик не просто пишет код

Разработка программного продукта начинается задолго до написания программы.

Упрощённая последовательность:

> **Проблема → Требования → Решение → Алгоритм и архитектура → Код → Тестирование → Продукт**

### Проблема

Сначала необходимо понять:

- какую задачу нужно решить;
- кто пользователь;
- что должно измениться после внедрения системы.

### Требования

Фиксируют:

- функции системы;
- ограничения;
- ожидаемое поведение;
- условия работы.

### Решение

На этом этапе выбираются:

- технологии;
- подход;
- структура системы;
- основные компоненты.

### Алгоритм и архитектура

Определяют, **как именно** будет решена задача и как будут связаны части системы.

### Код

Код реализует выбранное решение.

### Тестирование

Проверяет:

- корректность работы;
- соответствие требованиям;
- взаимодействие компонентов;
- поведение в разных сценариях.

### Продукт

Результатом становится готовое решение, которое можно использовать в реальной среде.

Работа разработчика включает не только написание кода, но также:

- анализ;
- проектирование;
- работу с данными;
- тестирование;
- развёртывание;
- сопровождение.

## 13. Инженерный кейс: Mars Climate Orbiter

В 1999 году NASA потеряло аппарат Mars Climate Orbiter при подлёте к Марсу.

Причиной стала несогласованность между программными компонентами:

- один компонент использовал английские единицы измерения;
- другой ожидал метрические.

Отдельные части системы могли работать корректно, но из-за несовместимого интерфейса вся система получила неверные данные.

Этот случай показывает, что качество ПО зависит не только от синтаксической правильности кода.

Необходимо контролировать:

- интерфейсы;
- форматы данных;
- единицы измерения;
- требования;
- взаимодействие компонентов.

Главный вывод:

> **Работа отдельного компонента не гарантирует правильную работу всей системы.**

---

## 14. Инженерный кейс: Knight Capital

В 2012 году после проблемного развёртывания программного обеспечения торговая система Knight Capital начала отправлять большое количество ошибочных заявок.

Компания понесла убытки примерно в **440 миллионов долларов**.

Проблема была связана не только с кодом, но и с организацией выпуска системы:

- неравномерным развёртыванием;
- старыми компонентами;
- конфигурацией;
- контролем версий;
- недостаточным контролем рабочего окружения.

Этот пример показывает, что надёжность ПО зависит от всего инженерного процесса.

Важны:

- тестирование;
- контроль версий;
- единообразное развёртывание;
- мониторинг;
- план отката;
- управление конфигурацией.

## 15. Почему ошибку нельзя всегда сводить к одной строке кода

В реальной программной системе сбой может быть вызван:

- неправильными требованиями;
- ошибкой алгоритма;
- дефектом кода;
- неправильным форматом данных;
- несовместимыми интерфейсами;
- ошибкой конфигурации;
- старой версией компонента;
- проблемой развёртывания;
- неправильными правами доступа;
- отсутствием тестирования;
- недостаточным мониторингом;
- ошибкой в организации процесса.

Поэтому профессиональный разработчик анализирует не только исходный код, но и систему целиком.

---

## 16. Основные выводы

Программное обеспечение — это не только приложение и не только код.

Современная программная система объединяет:

- программы;
- программные компоненты;
- данные;
- интерфейсы;
- системные сервисы;
- инфраструктуру.

ПО по назначению можно разделить на:

- системное;
- прикладное;
- инструментальное.

При этом реальный программный продукт часто состоит из нескольких уровней, которые должны корректно взаимодействовать друг с другом.

Главная задача разработчика — не просто написать код, а создать решение, которое:

- соответствует требованиям;
- корректно обрабатывает данные;
- взаимодействует с другими компонентами;
- тестируется;
- правильно развёртывается;
- стабильно работает в реальных условиях.

Ключевая профессиональная идея:

> **Разработчик не просто пишет код — он проектирует поведение программной системы.**
